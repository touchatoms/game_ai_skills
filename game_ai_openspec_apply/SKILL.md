# 游戏功能与 UI 工作流

统一承接需求分析 → OpenSpec 方案 → UI 契约 → 界面制作 → 验证交接。按用户本次请求选择阶段，不因提供了设计图便自动制作 UI，不因只做 UI 便重建需求方案。

## 选择模式

| 用户目标 | 执行内容 | 按需读取 |
| --- | --- | --- |
| 需求转 OpenSpec、生成 proposal/design/specs/tasks | 输入归一化、融合分析、生成方案、Explore 讨论 | [需求方案流程](references/from-doc.md) |
| 为已有变更制作或更新界面 / UIApply | 读取现有方案、确认输入、建立契约、制作和验收 | [UIApply 流程](references/ui-apply.md) |
| 从需求生成方案并制作界面 | 先完成方案，再复用同一 change 接着执行 UIApply | 先需求方案流程，到制作阶段再读 UIApply 流程 |

- 统一调用为 `$game_ai_openspec_apply`。
- `/opsx:from-doc` 仅在目标项目已配置对应命令时可用；本 Skill 不注册 OpenSpec CLI 子命令或 `/opsx:ui-apply`。
- 方案模式适用于各类游戏工程。UIApply 按目标模块选择 Unity UGUI、Cocos Creator 或 Cocos2d-lua，识别方法见 [UIApply 流程](references/ui-apply.md)。
- 这里的技术设计文档与 UI 设计效果图是不同输入，不能互相替代。

## 输入与复用

方案模式至少需要非空需求文字或可读取的 `.docx`、`.md`、`.txt` 需求文档；设计、接口文档可选。用 `-r/--requirement`、`-d/--design`、`-i/--interface` 或明确的自然语言字段指定。

UIApply 模式可直接指定已有 change，无需重新提供需求。制作前必须由用户明确提供或在本轮确认每页的四项输入：

1. 设计效果图具体路径。
2. UI 资源具体路径。
3. 工程内页面主产物的保存路径，按目标引擎和模块现用格式填写。
4. 与保存路径文件名（去扩展名）一致的产物名称。Unity 和 Creator 可沿用“Prefab 保存路径 / Prefab 资源命名”字段。

复用本轮已确认且未变更的输入；多页分别记录映射，不把一页的确认套到其他页面。缺失时列出具体项，暂停资源导入、页面制作和构建工具执行；可继续不依赖这些输入的方案工作。只生成方案时不强制索要四项输入。

先检查当前项目规则、工作区与已有 change/artifacts。同一范围复用已有进度，保留用户修改；不能以整合流程为由覆盖已有方案、勾选未完成任务或自动归档。

## 方案到 UI 的交接

需求涉及目标引擎 UI 时，在同一 `openspec/changes/<name>/` 下衔接：

- `design.md`：页面范围、状态、窗口框架、适配策略，以及业务逻辑与显示/绑定的分工；无依据的数值和节点路径标记待确认。
- 对应 `specs/*/spec.md`：记录来自需求的入口、交互、状态及异常表现和可验收场景；不把制作细节或假设写成已确认的业务规则。
- `ui-contract.md`：用 [契约模板](assets/ui-contract-template.md) 维护设计/资源来源、输出路径、节点与组件绑定、状态和验收条件。只做方案时可先记录已知内容，缺失项保持待确认；记录契约不代表具备制作条件。
- `tasks.md`：复用或新增一个 `UIApply` 分组，依次跟踪契约、资源导入、页面制作、结构、运行和视觉验收；每项只按实际结果勾选。业务 Apply 与 UIApply 可交错，但使用同一组节点/组件/资源路径契约。

UIApply 开始前核对方案中的页面状态与接口字段，读取已有业务脚本的真实路径和组件要求；发生冲突先定位受影响绑定与验收项，不另建一份互不一致的契约。仅本次任务需要时修改绑定代码；协议、奖励等业务实现仍由功能 Apply 负责。

需求、设计、接口、资源或绑定变更后，同步受影响的方案、契约与任务，并将对应旧验收证据标为失效。未受影响的有效验证继续复用。

## 完成与交付

- 方案交付：`proposal.md`、`design.md`、`specs/*/spec.md`、`tasks.md`、`analysis.md` 和来源明确的待确认问题；涉及 UI 时附契约与任务交接。按真实 CLI 结果报告验证状态。
- UI 交付：该引擎的页面主产物、依赖资源及项目所需的元数据、`ui-contract.md`、`ui-validation.md` 和证据截图。用目标项目的加载入口重新打开或实例化主产物，记录实际结果。
- 缺少编辑器、导出器或运行环境时，按实际完成的阶段交付，分别标明待导出、待加载、待运行或待视觉验收。真实窗口入口与设计图截图比对分别记录，不能以 CLI 任务完成或脚本生成成功替代验收。
- 报告本次执行模式、change、产物路径、实际验证结果及阻塞项。联合请求且制作条件满足时继续到验收；只有方案请求则在方案讨论后交付。
