# Cocos Creator 界面制作

1. 从工程元数据和相邻页面确认 Creator 版本、组件脚本写法、设计分辨率和资源组织。沿用本模块的 Bundle 或现有加载器，登记预制体文件（例如 `assets/activity/prefabs/ActivityPanel.prefab`）、Bundle 内加载键及对应窗口入口。2.x 与 3.x 使用各自工程已有的节点尺寸、坐标、组件和事件 API。
2. 在匹配版本的编辑器或项目已有编辑工具中，按契约建立或更新预制体。复用现有窗口根节点、列表项与公共控件，配置 SpriteFrame、字体、按钮事件和布局约束。核对序列化组件字段与脚本查找的子节点。通过项目导入流程获取资源引用，保留已有资产及脚本的 UUID 和配套 .meta。保存后重新打开并实例化，检查丢失的组件、空引用和失效的事件目标。[Creator 资源管理](https://docs.cocos.com/creator/2.4/manual/en/asset-workflow/) · [Creator 3.8 资源面板](https://docs.cocos.com/creator/3.8/manual/en/editor/assets/)
3. 从模块真实入口加载，核对 Bundle、路径大小写、图集帧、层级与触摸区域。执行打开、交互、关闭和再打开，检查异步加载完成时节点仍有效、监听按项目约定解除。按契约对照截图检查锚点、文本换行、裁剪和多分辨率布局。
4. 交付预制体、关联脚本或资源及适用的 .meta。若无法使用匹配版本的编辑器或项目工具，如实交付已完成的契约或源修改，将导入、实例化和实际预览的状态分别记入验收记录。
