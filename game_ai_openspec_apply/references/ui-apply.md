# UIApply 制作与验收

在目标游戏工程定位本次 change。指定 change 时读取其 proposal、design、specs、tasks 和已有 UI 契约；未指定时结合页面范围与 `openspec list --json` 选择。若多个候选仍无法区分，再询问用户。

## 从目标模块选择引擎

结合用户指定的项目、工程版本文件、相邻页面的可编辑源和实际加载代码选择下表的一条路径。混合仓库以该页面的消费方为准；单个 `.prefab` 后缀或 `assets` 目录不足以区分 Unity 与 Creator。若指定引擎与模块证据冲突，先澄清目标子工程。

| 引擎 | 识别依据 | 产物和执行规则 |
| --- | --- | --- |
| Unity UGUI | `ProjectSettings/ProjectVersion.txt`、窗口脚本与 UGUI 组件 | 在 `Assets/` 下保存 Prefab，按 [Unity 制作与验收](unity-ui-apply.md) 执行 |
| Cocos Creator | 工程配置中的 Creator 版本、同模块组件脚本与资源加载入口 | 在项目 `assets/` 中保存可实例化的预制体，按 [Creator 制作与验收](creator-ui.md) 执行 |
| Cocos2d-lua | Lua 客户端入口、窗口基类或工厂、模块的 UI 加载和资源发布规则 | 沿用 Lua 构建或现有布局导出链，按 [Lua 制作与验收](lua-ui.md) 执行 |

复用本轮已确认的设计图路径、资源路径、主产物路径和名称。确认前两项可读且对应页面，后两项与选定引擎和模块一致，目标可写，新文件允许尚不存在。四项存在缺口时只补对应项，制作任务保持待办。Lua 项目存在源文件、导出文件和运行时资源键时分别登记，避免将运行时二进制当作编辑源。

## 共用交接

实际查看设计图，以相邻页面为参照，在同一 change 的 [UI 契约](../assets/ui-contract-template.md) 里记录控件、节点路径、布局坐标、资源、交互状态和脚本绑定。将设计元素落实为可操作的页面控件，更新已有页面时保留人工修改和外部依赖的名称。业务任务与 UI 制作任务分别按实际完成情况勾选。

按所选引擎保存或导出页面，分别核对结构与引用、真实窗口入口的打开/操作/关闭，以及约定分辨率和状态下的截图。将实际工具版本、产物、加载入口、截图路径和每项结果写入 `ui-validation.md`。没有执行的阶段写明原因，编辑器预览只记录为预览证据。
